# MTR Excel 1.3 RC1 — единая база экспертных решений

Разработал Хапилин Виктор.

Распакуйте архив и запустите MTR_Excel.exe. Python и внешний интернет-сервис
для работы не нужны. PDF-программа этой версией не изменяется.

## Первый запуск

1. Нажмите «Общая папка» и выберите существующую папку подразделения.
   На всех компьютерах укажите **одну и ту же** папку, например
   `\\server\department\MTR_Knowledge`.
2. Первый подключивший её инженер становится администратором знаний.
   Автор определяется по учётной записи Windows; общие учётные записи
   считаются одним инженером.
3. Добавьте исходные файлы, укажите папку результата и нажмите «Обезличить».

Исходные файлы и их столбцы не перезаписываются. Повторный запуск создаёт
новый файл. Сохраняются XLSX, XLSM, XLS, CSV и все распознанные листы МТР.
Формулы XLSX/XLSM сохраняются, но формульные исходные строки не обучают базу.
Для XLS с формулами требуется предварительное сохранение в XLSX.

## Как инженер проверяет результат

В Excel исправляйте столбец **«Обезличенное наименование»**.
Для правильной строки поставьте **«Правильно»** в столбце «Решение инженера».
«Оставить как в исходном» возвращает исходное наименование.
Комментарий необязателен. Затем нажмите «Загрузить проверенный Excel».

Строка без отметки и без изменений **не считается проверенной**.
Исправление наименования считается решением и без отдельной отметки.
Повторная загрузка не увеличивает число независимых подтверждений.
Отдельную карточку или таблицу замечаний заполнять не требуется.

Можно проверять внутри программы: вкладка «Проверка строк», поиск по коду
или тексту, фильтр статуса, кнопки «Правильно», «Исправить»,
«Оставить как в исходном». Для группы разрешены подтверждение и возврат
каждой строки к её собственному исходному тексту. Текстовое исправление
применяется к одной строке. Зелёные строки также доступны для исправлений.
Сохранённое решение применяется при следующей обработке; исходный результат
сеанса остаётся в истории. Сеансы доступны после обработки на этом компьютере
или после возврата файла с другого компьютера.

Скрытые MTR_ROW_ID и MTR_SESSION_ID связывают результат с исходной строкой.
Не удаляйте эти столбцы. Сортировать нужно **все столбцы строки вместе**.
Повторы идентификатора, изменение исходных данных, формулы вместо результата
и неоднозначные совпадения не обучают базу; программа покажет перечень проблем.
Если ID удалён, используется только однозначное совпадение с сохранённым
исходным сеансом. Для старых результатов без сохранённого сеанса сначала
обработайте исходник новой версией.

## Как используются знания

- Подтверждённое решение по коду Автодокс применяется сразу. Принят договор:
  запись ресурса за кодом неизменна. Поддерживаются прежние варианты записи кода.
- Без кода требуется точное нормализованное наименование и завод.
- Исправление отдельного ресурса не становится безусловным правилом для всех.
- «Применить к похожим» создаёт буквальное KEEP/DELETE с заводом, категорией
  и ролью. KEEP сохраняет фрагмент, DELETE удаляет. После одного инженера
  это CANDIDATE, после двух — ACTIVE, после трёх — TRUSTED.
- Правила комплектующих требуют явного контекста привода, двигателя или
  комплектации и указания его производителя в той же части текста.
  Завод изделия не подставляется вместо завода комплектующего. При отсутствии
  такого контекста правило остаётся подсказкой, автоматического удаления нет.
- Разные решения инженеров дают DISPUTED и красный результат. Последнее
  решение одного автора заменяет только его предыдущий голос, сохраняя историю.
- Уровень доверия — состояние знания и число независимых инженеров,
  **не статистическая вероятность правильности**.
- Защищённые технические признаки, ГОСТ, ОЛ, IP, климат, размеры и параметры
  сохраняются. Экспертное решение, теряющее защищённый признак, хранится
  как предложение, но автоматически не применяется; результат красный.
- Согласованное исключение АЭРО ИКСИА сохранено: удаляется название завода,
  его обозначения оборудования сохраняются. Прочие бренды и реквизиты
  продолжают обрабатываться прежними правилами.

Статическая база RC8 остаётся исходной: 132 473 записи производителя,
218 дополнительных правил DELETE и 67 проверенных KEEP. Она не получает
фиктивных голосов инженеров. Удаления из правил получают устойчивый ID;
история исправления содержит автоматический результат и его основания.

## Совместная работа и восстановление

Общая папка — единственный источник общих решений. В неё записываются
неизменяемые события с UUID, автором и контрольной суммой. На компьютере
есть только индекс/кэш, исходные сеансы и очередь ещё не отправленных данных.
SQLite на сетевом диске не используется. Не размещайте локальный профиль
программы на сетевом диске.

Синхронизация выполняется при запуске, перед пакетом, после решения и раз
в минуту при простое. Пакет использует один снимок знаний. При обрыве связи
обработка идёт по последнему кэшу, новые решения ждут отправки. Состояние
связи и размер очереди видны сверху. Кэш с неотправленной очередью удалять нельзя.

В общей папке автоматически создаётся проверенный ZIP в `backups` при
изменении знаний или состава исходных сеансов. Копии сохраняются по дням
и версиям. Кнопка «Резервная копия» позволяет сохранить копию на другой носитель.
«Восстановить» проверяет контрольные суммы и извлекает базу только в пустую
папку. Затем её можно подключить через «Общая папка». Копия на том же диске
не заменяет резервирование диска подразделением.

Вкладка «База знаний» показывает статусы, голоса, примеры и полную историю,
позволяет искать, экспортировать Excel, подтвердить/оспорить контекстное правило.
Администратор может отключить ошибочное знание или вернуть его с указанием
причины. Обычный инженер может исправить собственное решение.
Список администраторов находится в `mtr-knowledge.json`; его изменение и
защита файлов общей папки регулируются правами Windows подразделения.
Автор в событии служит аудиту, а не заменяет доменную аутентификацию/ACL.

Журнал: `%LOCALAPPDATA%\MTR_Excel\mtr_excel.log`.
Конфигурация и локальный кэш: `%LOCALAPPDATA%\MTR_Excel`.
Ошибки запуска: `startup_error.log` в той же папке.

RC требует проверки реальной сетевой папки подразделения, её прав доступа
и поведения при отключении сети на рабочих компьютерах. Автотесты проверяют
одновременные записи и моделируют сбои; это не проверка конкретного SMB-сервера.

Для сборки: Python 3.12, `excel/requirements.txt`, PyInstaller,
`excel/build_exe.bat`. Тесты: `python -m pytest tests/excel -q`.
Командная строка: `MTR_Excel.exe --shared ПАПКА --output РЕЗУЛЬТАТЫ ФАЙЛ`.
Возврат: `MTR_Excel.exe --shared ПАПКА --import-review ФАЙЛ`.
Без настроенной общей базы CLI сохраняет прежний режим четырёх столбцов.
