# MTR Excel 1.8 RC3

Разработал Хапилин Виктор.

## Начало работы

1. Распакуйте ZIP в отдельную папку и запустите `MTR_Excel.exe`.
2. Выберите существующую папку `MTR_Knowledge`, если решения уже накоплены.
3. Добавьте Excel и нажмите **«Обезличить и проверить»**.
4. Проверяйте строки тремя кнопками:
   - **«Оставить результат программы»** — подтвердить предложенный текст;
   - **«Сохранить моё исправление»** — сохранить текст из поля результата;
   - **«Оставить как в исходном»** — сохранить исходное наименование целиком.
5. После проверки откройте папку с результатами. Исходный файл не изменяется.

Python и Microsoft Excel для работы EXE не нужны. Excel нужен только для ручного просмотра файлов.

## Как используются решения

Точное решение определяется сочетанием кода Автодокс, исходного наименования и завода.
Номера моделей, чертежей и технические признаки входят в исходное наименование и поэтому
участвуют в сопоставлении. Изменение наименования или завода при прежнем коде требует
новой проверки. Решения для разных вариантов одного кода хранятся независимо.

Порядок: точное решение инженера → подтверждённые правила для соответствующего контекста →
стандартный алгоритм. Для точного решения стандартный алгоритм повторно не запускается.
Например, после «Оставить как в исходном» для строки с МОС-3/1 и МОС-29.М1 оба обозначения
сохраняются в последующих обработках той же позиции.

Решение записывается в базу сразу после нажатия кнопки. Если программа закрылась до записи
итогового Excel, нажмите **«Продолжить последнюю проверку»**: принятые решения сначала
запишутся в результат и только после этого будут исключены из проверки.
Если файл перемещён, удалён или открыт другой программой с блокировкой записи, программа
сообщит об ошибке. Исходный файл можно обработать заново — база решений сохранится.

Пропущенные строки остаются непроверенными; программа сообщает их количество.
Одновременные противоречивые решения разных инженеров требуют проверки. Новое явное
решение заменяет уже известные противоречивые варианты, история сохраняется.

## Просмотр и исправление базы

Нажмите **«Выгрузить базу в Excel»**. В таблице доступны фильтры и поиск по коду Автодокс,
части исходного наименования, заводу, автору, дате и статусу. Количество независимых
инженеров показывает число подтверждений разными пользователями; повтор одного
пользователя не считается новым независимым подтверждением.

Для правки заполните **«Новое решение»**, выберите **«ИЗМЕНИТЬ»** и укажите причину.
Чтобы отключить или вернуть решение, выберите **«ОТКЛЮЧИТЬ»** или **«ВКЛЮЧИТЬ»**.
Для общего правила новое решение: **«ОСТАВИТЬ»** или **«УДАЛИТЬ»**.
Сохраните таблицу и нажмите **«Загрузить исправленную базу»**.

Не изменяйте исходные и скрытые служебные поля выгрузки. Устаревшие правки и изменения,
теряющие защищённые технические параметры, будут отклонены с указанием причины.
Статусы: **«ДЕЙСТВУЕТ»**, **«ОТКЛЮЧЕНО»**, **«НА ПРОВЕРКЕ»**, **«ТРЕБУЕТ ПРОВЕРКИ»**.
Кнопка **«Открыть папку базы»** открывает место хранения решений.

## Загрузка ранее обезличенных выборок

На стартовом экране нажмите **«Загрузить ранее обезличенную выборку…»**.

1. Выберите файл XLSX, XLSM, XLS или CSV, ранее проверенный инженером.
2. Выберите лист и строку заголовков. Сопоставьте столбцы исходного и обезличенного
   наименования; укажите код Автодокс и завод, если они есть. Проверьте предложенное
   программой соответствие. Одного обезличенного столбца недостаточно.
3. Нажмите **«Проверить выборку»**. Программа покажет новые решения, повторы,
   конфликты с базой и причины пропуска проблемных строк.
4. При конфликте по умолчанию сохраняется решение базы. Если нужен вариант выборки,
   выберите строку, сравните оба текста и отметьте **«Принять вариант выборки для этой позиции»**.
   Отключённые решения также требуют отдельного подтверждения для восстановления.
5. Отметьте **«Выборка проверена инженером»**, затем **«Добавить решения в базу»**.

Загружается только выбранный лист. Для другого листа повторите загрузку.
Повторный импорт одинаковых строк не создаёт новые подтверждения. Если в самой выборке
для одной позиции указаны разные результаты, все её варианты пропускаются: сначала
исправьте выборку. Строки с потерей защищённых технических параметров также пропускаются.
Исходный файл выборки не меняется. Данные о файле, листе, строке и инженере остаются в истории.
Импортированные решения применяются при точном совпадении кода, исходного текста и завода.
Вы можете затем выгрузить и исправить их обычными кнопками управления базой.

## Общая папка подразделения

Все инженеры выбирают одну папку базы. Общий журнал хранится в ней, SQLite используется
только как локальный кэш в `%LOCALAPPDATA%\MTR_Excel`. Старые журналы читаются без изменения
их файлов. На всех рабочих местах используйте RC3: старые версии не понимают новые
составные ключи. Перед обновлением сохраните копию существующей папки базы.

Если общий диск недоступен, решения остаются в локальной очереди отправки. Программа
сообщает об этом и отправляет их после восстановления связи при следующей синхронизации.
Реальную совместную работу в сетевой папке подразделения следует проверить при пилоте.

## Форматы и проверка

Поддерживаются XLSX, XLSM, XLS и CSV. XLS с формулами предварительно сохраните как XLSX.
Формулы в исходных полях XLSX/XLSM не обучают базу; такие строки отмечаются для проверки.

Сборка: `excel\build_exe.bat` на Windows с Python 3.12 и зависимостями
`excel/requirements.txt`, PyInstaller. Тесты: `python -m pytest -q`.
Проверка EXE: `MTR_Excel.exe --self-test` создаёт `SELF_TEST_OK.json`.
Журнал ошибок запуска: `%LOCALAPPDATA%\MTR_Excel\startup_error.log`.
