# MTR Excel 1.5 RC1 — обезличивание с последним решением за инженером

Разработал Виктор Хапилин.

Excel-модуль работает отдельно от PDF-модуля. Исходные файлы не перезаписываются.
Поддерживаются XLSX, XLSM, XLS и CSV.

## Главный принцип

Программа выполняет автоматическую обработку, показывает результат и причины,
но спорные накопленные решения не обязаны применяться без участия инженера.
По умолчанию режим **«Автоматически применять ранее подтверждённые решения»
выключен**.

Если галочка выключена:

- статические безопасные правила работают как раньше;
- подтверждённые KEEP могут только дополнительно защитить текст от удаления;
- ранее накопленные DELETE и исправления становятся подсказкой и строка идёт
  на проверку инженеру;
- конфликты решений остаются красными.

Если инженер сам включает галочку, ранее подтверждённые решения могут
применяться автоматически. Это осознанный пользовательский режим.

## Простое размещение

При обычном запуске появляется стартовое окно. По умолчанию база создаётся в
папке `MTR_Knowledge` рядом с программой. Поэтому можно, например, положить
программу в `D:\MTR_Excel` и работать без отдельного сервера.

Если несколько инженеров должны использовать одну базу, можно положить папку
программы на общий диск/сетевую папку либо выбрать одну общую папку базы на
всех компьютерах. В самой общей папке хранится журнал неизменяемых событий;
SQLite остаётся только локальным кэшем в `%LOCALAPPDATA%\MTR_Excel`.

Все пользователи, имеющие права Windows на запись в папку базы, могут работать
с решениями и управлением знаниями. Автор каждого изменения фиксируется по
учётной записи Windows, история не стирается.

## Результат обработки

К исходной таблице добавляются как минимум:

- `Выявленный завод/производитель`;
- `Обезличенное наименование`;
- `Статус проверки`;
- `Что именно удалено`.

При экспертном режиме также добавляются `Решение инженера`, комментарий,
источник знания, доверие и скрытые `MTR_ROW_ID` / `MTR_SESSION_ID`.

Исходные столбцы и исходный файл не изменяются. Каждый повторный запуск создаёт
новый результат.

## Проверка инженером

Проверять можно двумя способами.

### Внутри программы

На вкладке `Проверка строк` доступны поиск по коду/тексту, фильтр статуса,
исходное и автоматическое наименование и действия:

- `Правильно`;
- `Исправить`;
- `Оставить как в исходном`;
- `Применить к похожим` для буквального KEEP/DELETE в заданном контексте.

Зелёные строки также можно исправлять.

### Через готовый Excel

Инженер может открыть результат, исправить `Обезличенное наименование`, выбрать
`Правильно / Исправить / Оставить как в исходном`, сохранить файл и нажать
`Загрузить проверенный Excel`.

Строка без отметки и без изменения не считается проверенной. Повторная загрузка
одного и того же решения одного инженера не создаёт новый независимый голос.

Не удаляйте скрытые `MTR_ROW_ID` и `MTR_SESSION_ID`. Если файл сортируется,
нужно сортировать всю строку целиком.

## Импорт старых проверенных выборок

В стартовом окне есть `Импорт старых проверенных Excel…`.

Импорт принимается только если в таблице найдены одновременно исходное и
обезличенное наименование. Поддерживаются типичные заголовки кода Автодокс,
завода/производителя, исходного и обезличенного наименования.

Перед записью программа показывает:

- сколько решений готово к импорту;
- сколько уже есть в базе;
- сколько конфликтует с текущими решениями;
- сколько строк не прошло проверку.

Результат, теряющий защищённые технические признаки, не импортируется. При
конфликте пользователь отдельно решает, добавлять ли такое решение как новый
голос инженера.

## Выгрузка и редактирование базы

В стартовом окне есть:

- `Выгрузить базу для редактирования…`;
- `Загрузить отредактированную базу…`.

Это не прямое редактирование SQLite/JSON. Программа создаёт специальный Excel с
текущим ключом и решением. Редактируются только:

- `Новое решение`;
- `Действие` (`CHANGE`, `DISABLE`, `ENABLE`);
- `Причина изменения`.

При обратной загрузке программа проверяет, что ключ и текущее решение не
изменились с момента выгрузки. Каждое принятое изменение записывается новым
аудируемым событием; старая история сохраняется.

## Накопление знаний

Код Автодокс используется как сильный бизнес-ключ ресурса. Для связи конкретной
строки и конкретного сеанса используются внутренние `MTR_ROW_ID` и
`MTR_SESSION_ID`.

Без кода требуется точное нормализованное наименование и завод. Решение по одной
строке не превращается автоматически в глобальное правило для всех ресурсов.
Разные решения инженеров формируют `DISPUTED` и красный статус.

Защищённые признаки — ГОСТ, ОЛ, IP, климатические исполнения, размеры,
электрические и прочие технические параметры — не должны теряться. Решение,
которое их удаляет, блокируется или требует отдельной проверки.

## Технические ограничения

- XLS с формулами нужно предварительно сохранить как XLSX: старый BIFF-формат
  нельзя безопасно переписать без риска потери формул.
- Формулы XLSX/XLSM сохраняются, но формульные исходные строки не обучают базу.
- Для общей сетевой папки реальное поведение прав доступа и отключения сети нужно
  проверить на инфраструктуре подразделения.

Журнал: `%LOCALAPPDATA%\MTR_Excel\mtr_excel.log`.
Локальный кэш: `%LOCALAPPDATA%\MTR_Excel`.

Для сборки: Python 3.12, `excel/requirements.txt`, PyInstaller,
`excel/build_exe.bat`.

Тесты: `python -m pytest tests/excel -q`.

CLI примеры:

`MTR_Excel.exe --output РЕЗУЛЬТАТЫ ФАЙЛ`

`MTR_Excel.exe --auto-confirmed --output РЕЗУЛЬТАТЫ ФАЙЛ`

`MTR_Excel.exe --import-history СТАРАЯ_ВЫБОРКА.xlsx`

`MTR_Excel.exe --export-knowledge БАЗА.xlsx`

`MTR_Excel.exe --import-knowledge БАЗА.xlsx`
